# Logistic Regression: Feature Selection and Model Evaluation

## 1. Introduction

Following the initial logistic regression experiments, I revisited the feature selection process to investigate whether some of the engineered features contained overlapping information.

The objective was to reduce feature redundancy, improve model performance and establish a stronger logistic regression baseline against which other classification algorithms could be compared.

The evaluation considered both standard logistic regression and logistic regression using class weighting to account for the imbalance between defaulting and non-defaulting customers.

## 2. Feature Correlation Analysis

I used Spearman correlation analysis to investigate relationships between the engineered features and identify potential redundancy.

The analysis identified two areas of strong correlation:

- `latest_credit_utilisation` and `max_credit_utilisation` were strongly correlated with `average_credit_utilisation`.
- `bill_trend_intercept` was strongly correlated with `average_bill_amount`.

These features were considered to contain overlapping information. Retaining highly correlated features can introduce redundancy into a model, potentially making coefficient interpretation more difficult, particularly with logistic regression.

Consequently, I removed the following features:

| Removed feature | Reason |
|---|---|
| `latest_credit_utilisation` | Strong correlation with `average_credit_utilisation` |
| `max_credit_utilisation` | Strong correlation with `average_credit_utilisation` |
| `bill_trend_intercept` | Strong correlation with `average_bill_amount` |

The remaining features were retained for subsequent model training.

This approach aimed to preserve the most useful information while reducing unnecessary duplication between predictors.

## 3. Logistic Regression Evaluation

Following feature selection, I retrained the logistic regression models and evaluated their performance using the validation dataset.

The evaluation considered:

- Accuracy
- Precision
- Recall
- F1 score
- ROC-AUC

These metrics provide a more complete assessment than accuracy alone, particularly because the dataset contains a relatively small proportion of defaulting customers.

### 3.1 Standard Logistic Regression

The initial model used the default classification threshold of 0.5 and did not apply class weighting.

| Metric | Result |
|---|---:|
| Accuracy | 81.82% |
| Precision | 65.72% |
| Recall | 33.71% |
| F1 score | 44.56% |
| ROC-AUC | 76.33% |

The model achieved relatively high accuracy and precision, but recall was considerably lower.

This indicates that although the model was reasonably effective at identifying customers who would not default, it failed to identify a substantial proportion of actual defaulters.

The ROC-AUC score of 0.7633 indicates a moderate ability to distinguish between defaulting and non-defaulting customers.

### 3.2 Classification Threshold Evaluation

Rather than relying exclusively on the default threshold of 0.5, I evaluated alternative thresholds using the predicted probabilities.

| Threshold | Accuracy | Precision | Recall | F1 score |
|---:|---:|---:|---:|---:|
| 0.5 | 81.82% | 65.72% | 33.71% | 44.56% |
| 0.4 | 81.29% | 58.93% | 45.24% | 51.19% |
| 0.3 | 77.41% | 48.21% | 56.37% | **51.97%** |
| 0.2 | 73.49% | 42.49% | 62.98% | 50.75% |

Reducing the classification threshold increased recall, as more customers were classified as potential defaulters.

However, this came at the expense of precision and accuracy, because more non-defaulting customers were incorrectly classified as defaulters.

A threshold of 0.3 produced the highest F1 score of 0.5197, providing the best balance between precision and recall among the thresholds tested.

At this threshold, the model identified 56.37% of actual defaulters, compared with 33.71% at the default threshold of 0.5.

### 3.3 Logistic Regression with Balanced Class Weights

To address the imbalance in the target variable, I also trained logistic regression using:

`class_weight='balanced'`

This automatically adjusts the class weights during training to give greater consideration to the minority class.

The results at the default threshold of 0.5 were:

| Metric | Result |
|---|---:|
| Accuracy | 73.96% |
| Precision | 43.06% |
| Recall | 62.34% |
| F1 score | 50.94% |
| ROC-AUC | 76.48% |

Compared with standard logistic regression, class weighting substantially increased recall, from 33.71% to 62.34%.

However, precision and accuracy decreased. This reflects the model's greater tendency to classify customers as potential defaulters.

The F1 score increased from 44.56% to 50.94%, suggesting that class weighting provided a better balance between precision and recall at the default threshold.

### 3.4 Threshold Evaluation with Balanced Class Weights

I also evaluated alternative classification thresholds for the balanced model.

| Threshold | Accuracy | Precision | Recall | F1 score |
|---:|---:|---:|---:|---:|
| 0.5 | 73.96% | 43.06% | 62.34% | **50.94%** |
| 0.4 | 69.24% | 38.43% | 69.52% | 49.50% |
| 0.3 | 47.49% | 27.84% | 89.27% | 42.44% |
| 0.2 | 29.38% | 23.12% | 97.10% | 37.35% |

Lowering the threshold further increased recall, reaching 97.10% at a threshold of 0.2.

However, precision fell to 23.12%, meaning that fewer than one in four customers classified as potential defaulters actually defaulted.

The balanced model therefore became increasingly aggressive as the threshold decreased. Although this could be useful in applications where missing a defaulter is particularly costly, it would also generate a considerable number of false positives.

The highest F1 score for the balanced model was achieved at the default threshold of 0.5.

## 4. Comparison of Logistic Regression Configurations

The following table compares the three most useful configurations identified during the experiments.

| Configuration | Accuracy | Precision | Recall | F1 score | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| Standard, threshold 0.5 | **81.82%** | **65.72%** | 33.71% | 44.56% | 76.33% |
| Standard, threshold 0.3 | 77.41% | 48.21% | 56.37% | **51.97%** | 76.33% |
| Balanced, threshold 0.5 | 73.96% | 43.06% | **62.34%** | 50.94% | **76.48%** |

The results demonstrate that the choice of classification threshold and class weighting has a significant impact on the balance between precision and recall.

The standard model at a threshold of 0.3 achieved the highest F1 score, while the balanced model at 0.5 achieved the highest recall.

The standard model at 0.5 achieved the highest accuracy and precision, but identified substantially fewer actual defaulters.

The ROC-AUC scores were very similar across the configurations, indicating that the underlying ability to distinguish between the two classes remained broadly comparable.

## 5. Conclusions

The correlation analysis identified several engineered features containing overlapping information. Removing `latest_credit_utilisation`, `max_credit_utilisation` and `bill_trend_intercept` was followed by improvements in the logistic regression results.

Compared with the previous standard logistic regression model at a threshold of 0.5, the revised model achieved:

| Metric | Previous model | Revised model | Improvement |
|---|---:|---:|---:|
| Accuracy | 80.57% | 81.82% | +1.25 percentage points |
| Precision | 63.48% | 65.72% | +2.24 percentage points |
| Recall | 28.56% | 33.71% | +5.15 percentage points |
| F1 score | 39.40% | 44.56% | +5.16 percentage points |
| ROC-AUC | 75.10% | 76.33% | +1.23 percentage points |

Improvements were observed across all five metrics, suggesting that the revised feature set provides a stronger basis for prediction.

The experiments also demonstrated that class weighting and threshold selection can substantially influence classification performance.

For the current logistic regression benchmark, the standard model using a threshold of 0.3 achieved the highest F1 score (51.97%). The balanced model using a threshold of 0.5 provided a similar F1 score (50.94%) but higher recall (62.34%).

The choice between these configurations ultimately depends on the relative importance of identifying potential defaulters and avoiding false positives.

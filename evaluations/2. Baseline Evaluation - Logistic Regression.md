# Logistic Regression Model Evaluation

**Project:** Taiwanese Credit Card Default Prediction\
**Model:** Logistic Regression\
**Evaluation dataset:** Validation set\
**Feature set:** Engineered customer demographic, behavioural and financial features

## 1. Introduction

Logistic regression was selected as the first classification model for predicting whether a credit card customer would default on their next monthly payment.

The objective was to establish a baseline against which more sophisticated models, including decision trees, random forests and XGBoost, could subsequently be compared.

The target variable, `default.payment.next.month`, is binary:

- `0`: Customer does not default.
- `1`: Customer defaults.

The dataset contains an imbalanced distribution, with approximately 78% non-defaulters and 22% defaulters. Consequently, accuracy alone is insufficient for evaluating model performance.

The evaluation therefore considers accuracy, precision, recall, F1 score and ROC-AUC.

## 2. Model Configuration

The initial model used Scikit-learn's `LogisticRegression`, with numerical features standardised using `StandardScaler`.

A Scikit-learn Pipeline was used to ensure that the scaler was fitted against the training data only.

Initial configuration:

```
Pipeline([
    ('scaler', StandardScaler()),
    ('model', LogisticRegression(
        max_iter=1000,
        random_state=42
    ))
])
```

The model was trained using the training dataset and evaluated against the validation dataset.

Two training configurations were investigated:

1. Standard logistic regression.
2. Logistic regression using `class_weight='balanced'`.

The classification threshold was also varied to investigate the trade-off between precision and recall.

## 3. Evaluation Metrics

The following metrics were used:

| Metric    | Description                                                                                                           |
| --------- | --------------------------------------------------------------------------------------------------------------------- |
| Accuracy  | Proportion of all predictions that are correct.                                                                       |
| Precision | Proportion of predicted defaults that are actual defaults.                                                            |
| Recall    | Proportion of actual defaults correctly identified.                                                                   |
| F1        | Harmonic mean of precision and recall.                                                                                |
| ROC-AUC   | Ability of the model to distinguish between defaulters and non-defaulters across different classification thresholds. |

Recall is particularly important in this application because failing to identify a customer who subsequently defaults may carry a significant financial cost.

However, precision is also important because incorrectly identifying reliable customers as potential defaulters has its own consequences.

## 4. Standard Logistic Regression

The initial model used the default classification threshold of 0.5.

### Results

| Metric    | Result |
| --------- | ------ |
| Accuracy  | 80.57% |
| Precision | 63.48% |
| Recall    | 28.56% |
| F1        | 39.40% |
| ROC-AUC   | 0.7510 |

### Confusion Matrix

| <br>              | Predicted no default | Predicted default |
| ----------------- | -------------------- | ----------------- |
| Actual no default | 4,455                | 218               |
| Actual default    | 948                  | 379               |

Although accuracy was relatively high at 80.57%, recall was only 28.56%.

This means that the model identified fewer than three in ten customers who actually defaulted.

The result illustrates the limitations of relying on accuracy when working with an imbalanced dataset.

The ROC-AUC of 0.7510 was more encouraging, suggesting that the model had a reasonable ability to distinguish between the two classes, despite its relatively poor default classification performance at the 0.5 threshold.

## 5. Classification Threshold Experiment

The model's predicted probabilities were used to investigate alternative classification thresholds.

Rather than automatically classifying a customer as a defaulter when their predicted probability reached 0.5, thresholds of 0.4, 0.3 and 0.2 were also tested.

### Results

| Threshold | Accuracy | Precision | Recall | F1         |
| --------- | -------- | --------- | ------ | ---------- |
| 0.5       | 80.57%   | 63.48%    | 28.56% | 39.40%     |
| 0.4       | 80.42%   | 58.14%    | 40.92% | 48.03%     |
| 0.3       | 77.17%   | 48.55%    | 54.26% | **51.25%** |
| 0.2       | 73.43%   | 42.94%    | 61.19% | 50.47%     |

### Observations

Reducing the classification threshold increased recall, as more customers were classified as potential defaulters.

However, this came at the expense of precision and, to some extent, accuracy.

The best F1 score was achieved at a threshold of 0.3, increasing from 39.40% to 51.25%.

At this threshold, the model identified 54.26% of actual defaulters, compared with 28.56% at the default threshold.

This represents a substantial improvement in the balance between precision and recall.

The threshold of 0.2 achieved higher recall but a lower F1 score, indicating that the additional defaulters identified did not compensate for the increase in false positives.

## 6. Class Weighting Experiment

A second model was trained using:

```
LogisticRegression(
    max_iter=1000,
    random_state=42,
    class_weight='balanced'
)
```

This adjusts the relative importance of each class during training, giving greater weight to the minority class.

### Results at Different Thresholds

| Threshold | Accuracy | Precision | Recall | F1     |
| --------- | -------- | --------- | ------ | ------ |
| 0.5       | 74.10%   | 43.79%    | 60.36% | 50.76% |
| 0.4       | 69.57%   | 38.86%    | 65.56% | 48.79% |
| 0.3       | 46.08%   | 27.79%    | 89.98% | 42.47% |
| 0.2       | 27.87%   | 23.31%    | 98.79% | 37.73% |

### Confusion Matrix at Threshold 0.5

| <br>              | Predicted no default | Predicted default |
| ----------------- | -------------------- | ----------------- |
| Actual no default | 3,645                | 1,028             |
| Actual default    | 526                  | 801               |

### Observations

Class weighting significantly improved recall at the default threshold, increasing it from 28.56% to 60.36%.

However, precision decreased from 63.48% to 43.79%.

At a threshold of 0.2, recall reached 98.79%, meaning that almost all actual defaulters were identified. However, accuracy fell to 27.87%, indicating that an unacceptably large proportion of non-defaulters were also being classified as defaulters.

The balanced model therefore demonstrated a much stronger preference for identifying the minority class, but this came at a considerable cost in false positives.

## 7. Comparison of Model Configurations

The most interesting configurations are compared below.

| Configuration           | Accuracy | Precision | Recall     | F1         | ROC-AUC |
| ----------------------- | -------- | --------- | ---------- | ---------- | ------- |
| Standard, threshold 0.5 | 80.57%   | 63.48%    | 28.56%     | 39.40%     | 0.7510  |
| Standard, threshold 0.3 | 77.17%   | 48.55%    | 54.26%     | **51.25%** | 0.7510  |
| Balanced, threshold 0.5 | 74.10%   | 43.79%    | **60.36%** | 50.76%     | 0.7524  |

The standard model at a threshold of 0.3 produced the highest F1 score.

The balanced model at a threshold of 0.5 produced the highest recall of these three configurations.

The ROC-AUC remained almost unchanged across the two training approaches. This suggests that class weighting primarily changed the model's classification behaviour rather than materially improving its underlying ability to distinguish between the classes.

## 8. Conclusions

The logistic regression experiments established a useful baseline for the credit default prediction project.

Several conclusions can be drawn:

1. **Accuracy is potentially misleading.** The initial accuracy of 80.57% appeared encouraging, but recall of only 28.56% revealed that the model was failing to identify most actual defaulters.
2. **Classification thresholds matter.** Reducing the threshold to 0.3 substantially improved the F1 score and recall without requiring the model to be retrained.
3. **Class weighting improves minority-class detection.** Using `class_weight='balanced'` increased recall considerably, although precision and accuracy declined.
4. **There is a clear precision/recall trade-off.** Increasing the proportion of defaulters identified inevitably resulted in more non-defaulters being incorrectly classified.
5. **The ROC-AUC provides a useful baseline.** A score of approximately 0.75 suggests reasonable discriminatory ability, although there is considerable scope for improvement.

For subsequent model comparisons, standard logistic regression with a threshold of 0.3 will be retained as the provisional baseline configuration, achieving an F1 score of 51.25% and ROC-AUC of 0.7510.

The balanced model at a threshold of 0.5 will also be retained as an alternative where identifying a greater proportion of defaulters is the priority.

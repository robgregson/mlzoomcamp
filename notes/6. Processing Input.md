## API Input and Feature Preprocessing

The prediction API accepts a JSON object containing the original input features from the UCI Credit Card Default dataset.

The API also accepts a currency identifier, allowing monetary values to be supplied in different currencies.

The objective is to ensure that incoming data undergoes exactly the same currency normalisation, inflation adjustment and feature engineering as the original training dataset.

### 1. Input Parameters

The preprocessing function accepts two parameters:

| Parameter            | Type        | Description                                              |
|----------------------|-------------|----------------------------------------------------------|
| `currency_3_letters` | String      | Currency of the monetary values: TWD, GBP, USD or EUR    |
| `input_data`         | JSON object | Original dataset features and their corresponding values |

Example input:

```json
{
    "SEX": 2,
    "EDUCATION": 2,
    "MARRIAGE": 1,
    "AGE": 35,
    "LIMIT_BAL": 200000,
    "PAY_1": 0,
    "PAY_2": 0,
    "PAY_3": 0,
    "PAY_4": 0,
    "PAY_5": 0,
    "PAY_6": 0,
    "BILL_AMT1": 50000,
    "BILL_AMT2": 45000,
    "BILL_AMT3": 40000,
    "BILL_AMT4": 35000,
    "BILL_AMT5": 30000,
    "BILL_AMT6": 25000,
    "PAY_AMT1": 5000,
    "PAY_AMT2": 5000,
    "PAY_AMT3": 5000,
    "PAY_AMT4": 5000,
    "PAY_AMT5": 5000,
    "PAY_AMT6": 5000
}
```

The JSON object contains the original dataset features, rather than any engineered features. This keeps the API interface simple and consistent with the underlying dataset.

### 2. Preprocessing Pipeline

The `preprocess_input()` function converts the incoming JSON object into a Pandas DataFrame and applies the same transformations used during model training.

The processing sequence is:

1. **JSON conversion:** Convert the input dictionary into a single-row Pandas DataFrame.
2. **Currency conversion:** Convert all monetary fields into New Taiwan Dollars (TWD).
3. **Inflation adjustment:** Deflate monetary values to their equivalent 2005 purchasing power.
4. **Feature engineering:** Apply the same feature engineering transformations used when preparing the original training dataset.
5. **Feature alignment:** Ensure the resulting DataFrame contains the same feature names and column ordering expected by the trained model.

### 3. Implementation

The preprocessing function provides a single entry point for preparing prediction data.

```python
def preprocess_input(
    currency_3_letters: str,
    input_data: dict
) -> pd.DataFrame:

    # Convert JSON dictionary into a DataFrame
    df = pd.DataFrame([input_data])

    # Convert monetary values to TWD
    df = convert_currency_values(df, currency_3_letters)

    # Adjust monetary values for inflation
    df = deflate_currency_values(df)

    # Apply feature engineering
    df = engineer_features(df)

    # Ensure consistent feature names and ordering
    df = df[model_features]

    return df
```

### 4. Feature Engineering

Feature engineering is performed by the `engineer_features()` function.

Importantly, this is the same function used when preparing the original training dataset. This ensures that training and prediction data are transformed consistently.

No feature engineering logic should be duplicated within the API endpoint.

### 5. Calling the Preprocessing Function

The function can be called directly using the currency identifier and JSON input:

```python
df = preprocess_input(
    currency_3_letters="GBP",
    input_data=input_data
)
```

The resulting DataFrame is ready to be passed to the trained prediction model:

```python
prediction = model.predict(df)

probability = model.predict_proba(df)
```

### 6. Consistency Between Training and Prediction

Maintaining identical preprocessing between training and prediction is essential.

The same transformations must be applied in the same order to both datasets. This avoids training-serving skew, where the model receives differently processed data during prediction than it received during training.

The preprocessing functions should therefore be shared between the training and API components rather than implemented independently.

The intended architecture is:

| Stage                | Training                     | Prediction API        |
|----------------------|------------------------------|-----------------------|
| Input                | Original CSV dataset         | JSON object           |
| DataFrame conversion | Load CSV                     | Convert dictionary    |
| Currency conversion  | TWD (no conversion required) | TWD, GBP, USD or EUR  |
| Inflation adjustment | Original 2005 values         | Deflate to 2005       |
| Feature engineering  | `engineer_features()`        | `engineer_features()` |
| Feature alignment    | Training feature columns     | `model_features`      |
| Model                | Fit                          | Predict               |

This approach keeps the prediction API independent of the input currency while preserving compatibility with the original trained model.

### 7. Design Considerations

- The API accepts only the original dataset fields. Engineered features are generated internally.
- Unsupported currencies should raise a validation error.
- Missing, unexpected or incorrectly typed input fields should be rejected before prediction.
- The model feature list should be retained alongside the trained model to guarantee consistent feature ordering.
- Currency conversion rates and inflation assumptions should be treated as model configuration rather than embedded independently in the API code.

The result is a reusable preprocessing pipeline that separates the external API interface from the internal machine learning feature engineering process.

## Currency and Inflation Normalisation

The original credit card default prediction dataset was collected in Taiwan in 2005, with all monetary values denominated in New Taiwan Dollars (TWD).

To make the prediction API currency-independent, incoming financial data can be supplied in one of three currencies:

- TWD (New Taiwan Dollar)
- GBP (British Pound Sterling)
- USD (US Dollar)

Before passing the data to the prediction model, all monetary values are converted into TWD and adjusted for inflation to reflect their equivalent 2005 purchasing power.



### 1. Currency Conversion

The following fixed exchange rates are used:

| Currency | Conversion to TWD |
|----------|------------------:|
| TWD      |               1.0 |
| GBP      |              46.0 |
| USD      |              44.0 |

These are fixed experimental conversion rates rather than live foreign exchange rates.

The currency conversion function applies the appropriate exchange rate to all monetary fields.

```python
fx_curr_to_twd = {
    "TWD": 1.0,
    "GBP": 46.0,
    "USD": 44.0
}


def convert_currency_values(
    df: pd.DataFrame,
    currency_3_letters: str
) -> pd.DataFrame:

    currency = currency_3_letters.upper()

    if currency not in fx_curr_to_twd:
        raise ValueError(f"Unsupported currency: {currency}")

    fx_conversion_rate = fx_curr_to_twd[currency]

    for f in currency_fields:
        df[f] = df[f] * fx_conversion_rate

    return df
```

### 2. Inflation Adjustment

The original dataset dates from 2005. Monetary values supplied to the API therefore need to be adjusted for inflation to make them comparable with the original training data.

Taiwan has experienced approximately 33% cumulative inflation since 2005.

This means that a monetary value expressed in today's prices needs to be multiplied by:

\[
\frac{100}{133} = 0.7519
\]

In other words, TWD 133 today is approximately equivalent to TWD 100 in 2005 purchasing power.

Assuming a constant annual inflation rate, the equivalent annual rate is:

\[
r = 1.33^{1/21} - 1 \approx 1.36\%
\]

We can therefore calculate an inflation adjustment factor based on the difference between the current year and the original dataset year.

```python
data_year = 2005

annual_taiwan_inflation = 1.0136


def deflate_currency_values(
    df: pd.DataFrame
) -> pd.DataFrame:

    year_diff = datetime.datetime.now().year - data_year

    inflation_factor = annual_taiwan_inflation ** year_diff

    for f in currency_fields:
        df[f] = df[f] / inflation_factor

    return df
```

### 3. Normalisation Pipeline

The two transformations are applied sequentially before making a prediction:

1. Convert all monetary values into TWD.
2. Deflate monetary values to their 2005 purchasing-power equivalent.
3. Pass the normalised data to the prediction model.

The resulting monetary values should be comparable with those used to train the original model, regardless of whether the API input was supplied in GBP, USD or TWD.

### 4. Assumptions and Limitations

This approach makes several assumptions:

- Credit card repayment and default behaviour is sufficiently consistent across different countries and populations.
- The fixed exchange rates provide an adequate approximation for this experiment.
- Taiwan's cumulative inflation is an appropriate basis for adjusting the monetary values.
- A constant annual inflation rate is an acceptable approximation of the actual historical inflation profile.
- The relationships between credit limits, outstanding balances, repayment amounts and default risk remain sufficiently similar across countries and over time.

Currency and inflation normalisation address differences in monetary units and purchasing power. They do not, however, account for differences in income levels, credit availability, lending practices, consumer behaviour or economic conditions between countries.

Consequently, the model should be regarded as an experimental cross-currency prediction model rather than a model validated for international credit risk assessment.
